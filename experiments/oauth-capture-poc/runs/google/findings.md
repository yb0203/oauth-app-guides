# Google capture findings

- **Captured:** the console wall (1 redirect to `accounts.google.com`, sign-in only, no bot check, no cookie banner), 5 cropped docs screenshots (6 in total), and 16 of 16 quote checks on the live pages. Pages read: the two in `apps.json`, plus Google's "Create access credentials" page (linked as the next step, not in `apps.json`) to get the redirect URI step.
- **Stopped at:** Google sign-in. The Cloud console is a signed-in single-page app, so no real consent-screen, audience or client form was seen. Project creation and Gmail API enablement were not read (UNCERTAIN).
- **Human must:** sign in (and possibly accept Cloud terms), create the project, run the consent-screen setup, accept the User Data Policy, add test users, create the Web client, paste the redirect URI, then copy the client ID and secret into Composio. Later, for public use with sensitive or restricted scopes, request verification.
- **Google specifics verified:** External or Internal audience and Testing or In Production status exist (support page); the sensitive/restricted/non-sensitive review table (basic, additional, security assessment); the internal-app review exception; the 100 new-user cap on the unverified-app screen, for the project's lifetime; "Request verification for your app" link on the Audience page.
- **Not verified, so not claimed:** a 100 test-user cap in Testing mode (not on either page; the only 100 figure is the unverified-app cap), which Gmail scopes are sensitive vs restricted, and the exact meaning of Internal.
- **Docs oddity:** the credentials page says "client secrets aren't used for Web applications". That quote is real but looks wrong or dated for a server-side flow. Treat the secret step as UNCERTAIN until seen in the console.
- **Flaky or fixed:** a `jq` filter with `//` failed once when I tried to trim output, and I reran the screenshots. The `quote` command matches case-insensitively and with whitespace normalised, so a pass means the words are there, not that the casing or markup matches.
- **Time:** about 4 minutes of tool time for 1 console shot, 5 docs shots, 3 text reads and 16 quote checks.
- **Verdict:** useful for the Google-specific rules (audience, scope tiers, user cap, verification), which are the parts a reader most needs. Weaker for the procedure itself, since the real console forms are behind sign-in and the docs can drift from them. The docs-only evidence is why steps 2 and 12 stay UNCERTAIN. A signed-in handoff run would add the most value here.

## Main-session spot-check (added afterwards)
- The "100 test users in Testing mode" limit **does exist** on https://support.google.com/cloud/answer/15549945: "Projects configured with a publishing status of Testing are limited to up to 100 test users listed in the OAuth consent screen". It sits inside a collapsed section, which `inner_text` skips, so this run missed it. `capture.py quote` now also searches hidden text and reports `found_in: hidden_section`.
